# Demo policy proposals

Owner=proposal; synthetic-only; these are configurable demonstration rules, not official NGO/medical allocation, retention or eligibility policy.

- Real logic and nativeDB; external messages/OTP/template generation use explicit DEMO_PROVIDER configured before operations. Never auto-fallback after a failed real request.
- Three real auth roles; synthetic privileged accounts provisioned by explicit local bootstrap. No client role selector as auth. Any added account-management route requires current authorized actor and deployment Demo profile.
- Existing records retain their admitted legacy behavior. New journey events may use a sidecar policy with explicit draft/published/postponed workflow, registration windows, pool allocation and offer/acceptance policy; exact contract must be locked before workers implement it.
- Eligibility is an Organizer's explicit synthetic review. No clinical decision engine. Optional documents remain optional; Guest upload stays authentication-required.
- Offline IndexedDB synthetic-only, unencrypted, actor-partitioned. No offline attachment promise. Restore never auto-syncs; unknown outcome retains same immutable request. Reconcile first, bounded404 recovery, explicit same-ID resend only.
- Attendance is separate from registration/eligibility. A cancelled booking cannot become walk-in by check-in; walk-in explicitly creates a separate eligible operation subject to current capacity and policy.
- Closeout uses DB counts and blocks unresolved attendance; no hardcoded impact/attendance rates. Pending is not an occupied place.
- Run demo clock and seeded event dates will be recorded consistently; historical datasets remain unchanged. Eight namespace-owned curated synthetic events with1–3 licensed local images each, canary datasets separate.
